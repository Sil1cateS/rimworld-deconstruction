## 三、需要放到前面的类型与对象总览

目前逐类阅读主要沿 Editable → Def → BuildableDef → ThingDef 展开。整合时应先说明这是一条用于举例的分支，避免让读者以为所有定义都属于物品定义。

| 对象或类型 | 在框架中的位置 |
| --- | --- |
| Def | 定义的共同基类，保存名称、来源、扩展和公共处理入口 |
| BuildableDef | Def 的抽象派生类；ThingDef、TerrainDef 都从这里取得共同配置 |
| RecipeDef、StatDef、ResearchProjectDef | 各自直接继承 Def，分别描述配方、属性种类与研究项目 |
| CompProperties、GraphicData、StatModifier | 普通配置对象，并非每一个都继承 Def；可作为定义内部的数据 |
| ModContentPack | 从内容来源的角度组织资源与已经建立的定义 |
| DefDatabase&lt;T&gt; | 按类型保存定义引用，提供名称等查询 |
| DefOf 标记与 DefOfHelper | 标记需要绑定的类，并将已有定义引用写入公共静态字段 |

例如，长剑的 ThingDef 可以引用研究项目的 ResearchProjectDef，生成的 RecipeDef 又能引用长剑。这里有多种定义之间的联系，不是把所有内容塞进一个 ThingDef。

源码定位：基类（`Verse.Def.cs:9`）、抽象分支（`Verse.BuildableDef.cs:9`）、具体分支（`Verse.ThingDef.cs:13`、`Verse.TerrainDef.cs:9`、`Verse.RecipeDef.cs:12`、`RimWorld.StatDef.cs:10`、`Verse.ResearchProjectDef.cs:11`）、普通配置示例（`Verse.CompProperties.cs:10`、`Verse.GraphicData.cs:10`、`RimWorld.StatModifier.cs:8`）。

## 四、需要将局部流程图接成同一条主线

现有图分别解释了文件读取、模板合并、字段读取、多轮引用解析和后期整理。正式整合时，应再用一张全程图说明它们的相对位置；各复杂分支仍保留局部图。

全程图需要保留的顺序是：

1. 按活动内容包确定加载目录，加载程序集等内容，读取 Defs XML。
2. 合成统一 XML，执行补丁；在 ParseAndProcessXML 中登记并解析父模板。
3. 默认读取器建立 Def 与内部配置，按相应路径调用 PostLoad，并登记待连接引用。
4. 按来源保存定义，再由各 DefDatabase 收集入库。
5. 首轮名称引用解析、早期 DefOf 绑定与相关早期处理。
6. PreResolve 生成；其中还穿插一轮名称引用解析，随后继续生成。
7. 最后一轮名称引用解析并清理记录，最终 DefOf 绑定。
8. 前置系统准备，各类型的 ResolveReferences，PostResolve 生成与后置系统准备。
9. 开发者模式下的整批 Def 配置检查、键位设置初始化、短哈希分配与查询字典建立。

这是定义主线的概览，省略了补丁检查与完成处理等已在局部说明的调用。语言、着色器、全局缓存与后续资源函数在总图中标明位置即可；不能把“交给 ExecuteWhenFinished”统一画成“已经执行完毕”。

源码定位：文件到定义（`Verse.LoadedModManager.cs:56`、`Verse.LoadedModManager.cs:437`）、入库后的主流程（`Verse.PlayDataLoader.cs:94`）、生成器内部解析（`RimWorld.DefGenerator.cs:11`）。

## 五、结尾应收束查询接口与准备程度

需要把“能取得定义对象”与“所有关联都已准备完成”分开。查询在加载中间也会发生，例如生成逻辑会使用已经入库的定义；不能把示意流程理解为最后一步以前都无法查询。

| 时点 | 已有的能力 | 仍须注意 |
| --- | --- | --- |
| Def 刚从 XML 建立 | 已有对象及相应字段，部分 PostLoad 已按路径调用 | 不保证已入全局库，也不保证 Def 引用已连接 |
| 加入类型数据库 | 可以通过相应列表和名称字典取得定义 | 引用、生成内容、类型自身整理与短哈希可能仍在后面 |
| 完成相应阶段的绑定与整理 | 定义取得更多关联、默认值与缓存；静态字段可以保存已有定义引用 | 各种准备分别由具体调用保证，不存在通用的“全部有效”承诺 |
| 短哈希分配并建立对应字典 | 可通过已初始化的短哈希查询入口查找 | 这不是物品实例 ID，也不代替名称、类型与来源信息 |

本章最后可并列说明三种取得定义的方式：显式查询 DefDatabase、读取已绑定的 DefOf 静态字段、沿其他对象已经保存的 Def 引用访问。三者都围绕已存在的定义对象，不会仅因读取引用就重新解析 XML。

源码定位：名称查询（`Verse.DefDatabase.cs:251`）、批量整理（`Verse.DefDatabase.cs:143`）、静态绑定（`RimWorld.DefOfHelper.cs:27`）、短哈希字典（`Verse.DefDatabase.cs:302`）。
